# 🚀 OJ 复活实录：从 HTTP 500 到第一个 AC

## 前言：上篇埋的雷，炸了

还记得上篇《服务器抢修》结尾说的那个决定吗？修服务器时我顺手清理了宿主机上一个"半配置状态"的 MySQL 软件包，当时的判断是——**业务数据库都跑在 Docker 容器里，宿主机这个应该没用**。

结果上周想用基地的 **OJ 系统**（在线判题平台，2022 年搭的 HUSTOJ，用来办招新机试）办今年招新，打开一看：

**HTTP 500。** 整个站直接罢工。

一查才明白：OJ 的数据库 `jol` **恰恰就存在宿主机 MySQL 里**。那篇故障报告里写的"业务数据库实际运行于 Docker 容器，不受影响"——**是我当时的误判，这雷是我自己亲手埋的** 😇

好在排查发现 `/var/lib/mysql/jol` 数据文件完好。行，自己埋的雷，跪着也要排完。

## 💥 坑一：无外网服务器怎么装回 MySQL

第一反应是 `apt install mysql-server`——结果服务器**没有外网**，apt 卡死在 `0% [已连接到...]`，连换 IPv4 都一样。

解法：**离线安装**。用自己电脑从清华镜像下载 .deb 包，拖进 Xshell 传到服务器：

```bash
# 按依赖顺序安装
dpkg -i mysql-client-core-8.0_*.deb
dpkg -i mysql-client-8.0_*.deb
dpkg -i mysql-server-8.0_*.deb
dpkg --configure -a   # 收尾，补齐半配置状态

systemctl start mysql
```

装完启动，`jol` 库完好无损：**221 道题、429 个用户、8066 条提交记录**，一个不少。✅

但打开网页一看——**页面要卡整整 30 秒才加载出来**，而且首页整个花掉了。行吧，一个坑填完还有下一个。

## 🐌 坑二：每小时卡 30 秒的元凶

用 `curl -w "%{time_total}"` 一测，页面加载精确地停在 **30.036 秒**——这个"整 30 秒"太可疑了，八成是某个**超时等待**。

顺着翻 OJ 的源码，在公共初始化文件里抓到了真凶：

```php
// init.php：如果背景图设置为 "bing"
$data = curl_get("https://cn.bing.com");   // CURLOPT_TIMEOUT = 30
```

好家伙，HUSTOJ 自带一个「**每小时从必应抓取当日壁纸**」当背景图的功能。而这台服务器**没有外网**：

- 每个小时的**第一个访问者**，触发抓取 → 干等 30 秒超时 → 页面才加载
- 之后一小时内的访问者走缓存，秒开


**修复**：在配置里把壁纸功能关掉（`$OJ_BG` 置空），30 秒卡顿从此消失。这台服务器没外网，一切"偷偷联网"的功能都是这个下场。

## 🎨 坑三：首页花屏成必应

更绝的是背景图功能的另一个副作用：抓取失败后，它把**下载回来的整页必应 HTML（132 KB）当成壁纸地址**塞进了页面的 CSS 里，双引号直接把样式表撑爆——浏览器把这 132 KB 当正文渲染了出来。

所以「页面花掉」和「卡 30 秒」是同一个根因的两副面孔。上面的修复一并解决，验证：

```bash
curl -sL http://localhost/index.php | grep -c -i "bing"
# 输出 0 = 页面里再无必应的任何痕迹
```


## ✅ 复活验收

全部修完，按清单过了一遍：

- 首页加载 **0.038 秒**（修复前 30.036 秒）
- 页面里必应残留 **0 处**（修复前 10 处）
- 数据完好：**221 道题 / 429 个用户 / 8,066 条提交**
- 浏览器登录 admin 成功，实测提交一道题，**判题返回绿色「正确」** 🎉

这台半年没人管的老机器，满血复活。

## 📋 复盘总结

| 故障 | 根因 | 修复 |
|------|------|------|
| HTTP 500 | 宿主机 MySQL 被误删 | 离线 dpkg 装回，数据零丢失 |
| 页面卡 30 秒 | 壁纸功能每小时联网超时 | 关闭联网壁纸功能 |
| 首页花屏 | 抓取失败的 HTML 污染样式 | 同上，一并解决 |
| admin 密码失传 | 自定义哈希算法无人知晓 | 调用 pwGen 重新生成 |
| 重启后再瘫 | MySQL 没设开机自启 | systemctl enable |

四条教训，句句带血：

1. **动服务器前先做依赖三连查**：`docker ps`、端口占用、进程列表——这次的 500 就是不查依赖直接卸载的代价
2. **改配置先备份**，出事能一键还原
3. **凡「偷偷联网」的功能，在无外网服务器上一律关掉**——它们的宿命就是卡满超时然后失败
4. **开机自启必须显式 enable 并验证**，别以为服务在跑就万事大吉

## 写在最后

从 500 到 AC，前后折腾了两天。最有成就感的瞬间，是看到提交记录页上那条绿色的「正确」——半年没人管的老系统，数据一条没丢，判题机照常运转。

11 月上旬的招新机试就靠它了。而这次也给我上了最重要的一课：**对服务器上的每个服务，都要知道"它是谁的依赖"**——你随手删掉的，可能是别人系统的心脏。
