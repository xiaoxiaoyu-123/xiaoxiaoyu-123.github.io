# Git团队开发项目使用教程

## 前言

这篇教程源于我第一次参与团队项目开发的经历。当时从学长那里接手基地项目，需要使用Git来管理团队代码，
过程中积累了一些实用经验。在此记录下来，希望能帮助其他初次接触Git团队协作的开发者。

## 个人仓库使用

每个开发人员通常会有自己的个人仓库，用于存储和管理个人代码。在创建并初始化仓库后，日常使用主要遵循以下三个基本步骤：

```bash
# 添加所有修改到暂存区
git add .

# 提交更改并添加提交信息
git commit -m "提交信息"

# 推送到远程仓库的main分支
git push origin main
```

## 团队合作开发流程

当进行团队协作时，项目会有一个共享的中央仓库，所有团队成员共同维护。以下是完整的团队开发流程：

### 1. 同步最新代码
每次开始开发前，务必先获取远程仓库的最新代码，确保本地代码与团队同步：

```bash
git pull origin main
```

### 2. 创建功能分支
为了避免直接修改主分支，需要创建一个新的分支来开发功能:

```bash
# 创建并切换到新分支（分支名建议使用有意义的名称）
git checkout -b feature/功能名称（分支名）
```
后续进行开发,如果需要切换回主分支，
使用 `git checkout main` 即可，切换回分支是`git checkout feature/功能名称（分支名）`。

### 3. 开发并同步代码
在分支上进行开发，提交代码前再次同步最新的main分支代码，避免冲突：

```bash
git pull origin main
```

### 4. 提交并推送代码
完成开发后，将代码提交到你的分支：

```bash
# 添加修改
git add .

# 提交更改
git commit -m "功能描述"

# 推送到远程分支
git push origin feature/功能名称（分支名）
```

### 5. 合并分支（管理员操作）
当功能开发完成并通过测试后，管理员将分支合并到main分支：

```bash
# 切换到main分支
git checkout main

# 合并功能分支
git merge feature/功能名称（分支名）

# 推送到远程main分支
git push origin main
```
## 日志及版本跳转
当你需要查看项目历史记录或回滚到特定版本时，可以使用以下Git操作：
- 1.查看提交日志：
  ```bash
  git log
  ```
- 2.查看指定版本的代码：
  ```bash
  git show 提交哈希值
  ```
- 3.跳转到指定版本：
  ```bash
  git checkout 提交哈希值
  ```

## 总结

通过以上流程，团队成员可以有序地协作开发，避免代码冲突，保证项目的稳定性和可维护性。Git的分支管理机制为团队开发提供了灵活而强大的支持，掌握这些基本操作将大大提高团队开发效率。

希望这篇教程对大家有所帮助！
